# Учет расходов · лабораторная № 3

Android-приложение на Kotlin и Jetpack Compose для ручного учета покупок по четырем банкам. Исходное задание — [task-03.md](https://github.com/itmo-kotlin-android-tech-26-27/.github/blob/main/profile/practice/task-03.md). [Макеты предыдущей лабораторной](https://www.figma.com/design/e4l7p9wnNFsmVyn1Iczug2/?node-id=4-39).

## Запуск

Распакуйте проект и откройте папку с `settings.gradle.kts` в Android Studio с поддержкой AGP 9.4.1. Выберите встроенный JDK студии и установите Android SDK Platform 37. Для первой синхронизации нужен доступ к Google Maven, Maven Central и Gradle Plugin Portal. Запустите конфигурацию **app** на эмуляторе или устройстве с Android 8.0 (API 26) или выше.

На Windows в PowerShell из корня проекта:

```powershell
.\gradlew.bat assembleDebug testDebugUnitTest
```

На macOS/Linux: `sh gradlew assembleDebug testDebugUnitTest`. APK после сборки — `app/build/outputs/apk/debug/app-debug.apk`.

## Сценарий защиты

1. При первом запуске в текущем месяце есть четыре вымышленные покупки. Кофе в Т-Банке — 420 ₽, метро в Сбере — 180 ₽, продукты в Альфа-Банке — 2 350 ₽, кино в ВТБ — 1 200 ₽. Всего 4 150 ₽.
2. Нажмите **Добавить расход**. Введите **590,50**, выберите **Продукты** и **Альфа-Банк**, оставьте сегодняшнюю дату. Поверните устройство. Введенные поля сохраняются.
3. Нажмите **Сохранить расход**. Итог текущего месяца составит **4 740,50 ₽**, по категории «Продукты» — **3 360,50 ₽**. Эти суммы относятся к исходному набору без других изменений.
4. Системная кнопка «Назад» откроет сохраненную покупку для редактирования. Повторное сохранение обновляет запись с тем же ID. Кнопка **К истории расходов** возвращает к месяцу этой покупки.
5. На экране истории выберите предыдущий месяц без покупок. Появится сообщение об отсутствии расходов и кнопка добавления. Можно также выбрать категорию без записей. Пустая сумма, ноль, больше двух знаков после запятой и незаполненные обязательные поля вызывают ошибку формы.

## Маршруты

| Route | Аргумент | Экран |
| --- | --- | --- |
| `history` | — | История, месяц и фильтр по категории |
| `form/{id}?month={month}` | `new` или ID покупки, выбранный месяц (необязательно) | Добавление или изменение суммы, категории, банка, даты и комментария |
| `result/{id}` | ID сохраненной покупки | Сумма покупки и итоги месяца по категориям |

## Реализация

У каждого экрана своя Hilt ViewModel. Состояние передается через StateFlow, UI подписывается через collectAsStateWithLifecycle. Аргументы маршрутов и поля формы доступны через SavedStateHandle. Hilt предоставляет реализацию интерфейса ExpenseRepository. Покупки записываются в локальный JSON в SharedPreferences и сохраняются после перезапуска. Пользователь может отредактировать расход или удалить его с подтверждением.

Суммы хранятся целым числом копеек. В файле Expense.kt находятся чистые функции проверки суммы, отбора по месяцу и подсчета итогов. Первая версия поддерживает рубли и ручной ввод. Название банка — поле записи. Интеграции с банками, импорт файлов и облачная синхронизация отложены.

## Проверка интерфейса и скриншоты

На подключенном тестовом устройстве запустите инструментальный тест. Он заполняет форму, пересоздает Activity, проверяет возврат и повторное сохранение, затем удаляет свою тестовую запись. Используйте чистый тестовый эмулятор, чтобы воспроизвести исходные суммы.

```powershell
.\gradlew.bat connectedDebugAndroidTest
adb pull /sdcard/Android/media/ru.itmo.expenses/lab3-screens screenshots
```

Тест создает PNG фактических экранов: `01-history.png`, `02-form.png`, `03-result.png`. Для команды копирования adb должен быть доступен из Android SDK Platform Tools.
